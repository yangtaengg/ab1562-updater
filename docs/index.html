펌웨어 파일

사이트는 펌웨어를 호스팅하지 않습니다. 벤더 배포처에서 받은 파일을 앱에서 직접 선택하세요. 앱은 크기와 SHA-256을 검사합니다.

업데이트 순서

  1. 이어폰 양쪽을 60% 이상 충전하고 케이스에서 꺼냅니다.
  2. macOS는 도우미 앱을 실행하고 Chrome에서 http://127.0.0.1:8768/을 엽니다. Windows/Linux는 웹 업데이터를 엽니다.
  3. 좌우 펌웨어 파일을 선택합니다. 파일이 맞으면 확인됨이 표시됩니다.
  4. 기기 연결하기를 누르고 제품, 버전, 배터리, 상태 검사를 기다립니다.
  5. 업데이트 버튼을 누르고 확인 창에서 시작합니다. 완료될 때까지 창을 닫지 마세요.
  6. 기기가 재시작되면 다시 연결하기를 눌러 양쪽 버전을 확인합니다.
중간에 끊기면 앱이 임의로 Commit을 다시 보내지 않습니다. 다시 연결해서 양쪽 상태를 읽고, 이미 전송된 쪽은 SHA-256을 비교해 건너뜁니다.

연결 방식

macOS

Chrome의 Web Serial은 macOS가 알려주는 RFCOMM 채널 1로 열려고 하지만 실제 FOTA 채널은 3입니다. 웹 API에는 채널 선택 기능이 없어 도우미 앱이 필요합니다.

macOS 도우미

Windows / Linux

Chrome 또는 Edge의 Web Serial을 사용하는 실험적 경로입니다. OS의 Bluetooth 스택이 서비스 UUID로 채널을 해석하므로 macOS와 다를 수 있지만, 이 프로젝트에서 실물 검증은 아직 macOS에서만 했습니다.

자주 묻는 질문

Chrome만으로는 왜 안 되나요?

macOS의 RFCOMM 채널 해석 문제와 BLE 서비스 부재 때문입니다. 자세한 내용은 첫 화면에 정리했습니다.

업데이트 후 버전이 안 바뀌었어요.

Commit 응답이 유실됐을 수 있습니다. 다시 전송하지 말고 재연결해서 양쪽 버전과 상태를 확인하세요. 앱은 확인된 버전만 완료로 기록합니다.

배터리가 부족하다고 나옵니다.

양쪽 모두 60% 이상이어야 합니다. 충전 후 다시 연결하세요.

파일이 맞지 않는다고 나옵니다.

좌우 파일을 바꿔 선택했거나, 다른 배포 패키지일 수 있습니다. 위 표의 이름과 SHA-256을 확인하세요.

다른 모델도 되나요?

지원하지 않습니다. 유사한 AB1562 계열이라도 파티션과 프로토콜이 다를 수 있습니다.

로그를 보내려면?

macOS 앱 창의 로그를 복사하거나, 웹 업데이터의 브라우저 콘솔 오류를 함께 보내 주세요. 기기 상태와 버전, 파일 해시가 도움이 됩니다.
